# Codex Plugin: add this repository by repository specifier

Issue: HiroshiYoshino/ux-ui-agent-skills#11 (parent #2). Status: the route below is
verified on Codex CLI only. Desktop app and IDE extension are not verified.

## What the official model is (and what it is not)

Codex does not add a plugin directly from a repository. The supported route has two steps:

1. Register the repository as a **marketplace** (a catalog of plugins).
2. Add a **plugin** from that marketplace.

```bash
# 1. register the repository (owner/repo, optional @ref; a git URL or --ref also work)
codex plugin marketplace add HiroshiYoshino/ux-ui-agent-skills@<branch-or-tag>

# 2. add the plugin, then start a new Codex session in your project
codex plugin add ux-ui-agent-skills-codex@hiroshiyoshino-ux-ui-agent-skills
codex plugin list
```

`@<branch-or-tag>` is required until this work is merged to the default branch. Without
it Codex reads the default branch, which at the time of the check (revision
594b262) carried only the Claude Code catalog, and registered a marketplace named
`ux-ui-agent-skills` that is not this plugin.

| Value | Setting |
|---|---|
| Marketplace name | `hiroshiyoshino-ux-ui-agent-skills` (`.agents/plugins/marketplace.json`) |
| Plugin name | `ux-ui-agent-skills-codex` |
| Plugin version | `3.0.0-codex.N` (see `.codex-plugin/plugin.json`) |
| Source of truth | `https://github.com/HiroshiYoshino/ux-ui-agent-skills` |
| Skill ids in Codex | `ux-ui-agent-skills-codex:<skill>` |

The name and the prerelease version are deliberately distinct from the upstream
plugin (`plugin87/ux-ui-agent-skills`, by Thientan Soparat, MIT) and from the npm
package. This repository does not assume rights to the npm name, and nothing here is
published to npm. The MIT license and the upstream credit are kept in `LICENSE` and the
plugin `interface` text.

## What the plugin contains

The plugin root is the repository root, so scripts, tokens and the design-system library
travel with it and no manual build or original checkout is needed.

- `.codex-plugin/skills/`: 23 skills generated by `scripts/build_codex_plugin.mjs` and
  **committed**, because Codex runs no build step. CI and the tests run
  `node scripts/build_codex_plugin.mjs --check`, which fails on drift.
- `.codex-plugin/mcp.json`: the `ux-ui-kit` MCP server (`node mcp/server.mjs`).
- `.codex-plugin/capabilities.json`: generated list of what is and is not available.
- Excluded Claude-only skills: `critique`, `observe`, `scaffold-project`.

To change anything distributable: edit the sources, run `node scripts/build_codex_plugin.mjs`,
bump the version in `.codex-plugin/plugin.json` (Codex pins installs by version) and add a CHANGELOG note.

### Published version versus local development version

| Capability | Published plugin | Local checkout (`init --agent codex` / Claude) |
|---|---|---|
| Skills | 23, namespaced | Claude skills / AGENTS.md route |
| Claude hooks (edit tracking, stop gate) | **Off** (`"hooks": {}`); never shown as enabled | Claude Code only |
| Browser gates | Need `playwright` in your project; without it they report failure, never a pass | same |
| MCP `run_gate`, `review_ui` | Absolute paths only; relative paths are refused with "Nothing was measured" | relative paths allowed |

### Plugin root versus your project

Skills tell the agent to resolve `<plugin-root>` to an absolute path (three directories
above the skill's `SKILL.md`) and to run commands from **your project**, so `CLAUDE.md`
is read as your `AGENTS.md`. Nothing depends on the clone location or the current directory.

## Trust, update, removal, ownership

- Trust and approvals are Codex's. This plugin ships no hooks, so nothing needs hook
  trust; MCP and tool approvals are not bypassed. No credentials are stored in the
  plugin (the validator scans for them).
- Update: `codex plugin marketplace upgrade`, then re-run `codex plugin add ...` after a
  version bump. A new version replaces the old cached version directory.
- Remove: `codex plugin remove ux-ui-agent-skills-codex@hiroshiyoshino-ux-ui-agent-skills`,
  then `codex plugin marketplace remove hiroshiyoshino-ux-ui-agent-skills`. Only the
  plugin cache and its `config.toml` entries are touched; your `AGENTS.md`, other config
  and project files are not.

## Coexistence with the other Codex routes

`npx ux-ui-agent-skills init --agent codex` (AGENTS.md plus gates in your project) is
unchanged and can be used with the plugin. Do not also copy the same skills into
`.agents/skills`: Codex would list each skill twice (plain and `ux-ui-agent-skills-codex:`
namespaced). To migrate, remove the copied skill folders, then add the plugin.
